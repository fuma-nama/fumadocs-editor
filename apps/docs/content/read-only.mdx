## The `editable` prop

`editable={false}` shows the document read-only: typing is off, and every
piece of mutating chrome — slash menu, bubble and block menus, mobile bar,
drag handles — is gone. Selection and copy still work, and the raw MDX tab
becomes read-only too. The prop is live; flipping it doesn't remount the
editor.

It's a plain TipTap passthrough with no opinion about _why_ a document is
read-only — that's yours to decide: a viewer role, a published snapshot, a
document checked out by someone else.

## Wiring it to auth

The [auth layer](/auth) enforces scopes server-side and only _reports_ them
to the client: a `read` reply carries `writable`. Connecting that data to the
prop is deliberately consumer code —

A read-only user who tampers with the client and types anyway changes
nothing: the server refuses the writes, and under [collab](/collab) their Y
updates are dropped while they keep receiving everyone else's. The `editable`
wiring is honest UI, not the security boundary.

Under collab, the same data sits on the session: `collabSession.access`
(from `@fumadocs-editor/sync/collab`) holds `{ user, writable }` from the
document-open handshake.
