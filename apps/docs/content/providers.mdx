## Host concerns

The editor does not know where pasted images go, or which documents exist
for links. Both are provider props: small interfaces your host implements.

Without `media`, paste/drop upload is off; images are added by URL.
Without `files`, the include picker and `[[` page-link autocomplete are
plain text inputs. Everything else still works.

## MediaProvider

<include meta='title="providers.tsx"'>../examples/providers.tsx#media</include>

`upload` stores the file and returns the `src` written into the document
(keep it relative if that is what the site expects). `resolve` maps
document srcs to display URLs so relative paths still preview.

On the [sync dev server](/sync#the-dev-server), its endpoints do the
storing:

<include meta='title="dev-media.tsx"'>../examples/providers-dev.tsx</include>

Uploads land in `<root>/assets`. Checked server-side before store: content
type against `upload.types` (default `image/*`) and size against
`upload.maxBytes` (default 10 MiB). With [auth](/auth), upload also needs
`write` on the stored path. Pass the payload in `AUTH_HEADER` as the
example does.

## FileProvider

<include meta='title="providers.tsx"'>../examples/providers.tsx#files</include>

Return the relative paths to write into the document (relative to the open
document, e.g. `./shared/props.mdx`). They power:

- the `<include>` path region autocompletes in place
- typing `[[` opens page-link suggestions

On the dev server, `transport.list()` minus the open document is usually
enough.
