## The authority model

With collab on, the server holds the document:

- One Y.Doc per open file, **single writer**. Client edits converge in the
  Y.Doc; the server serializes to disk (debounced, byte-preserving for
  untouched blocks).
- Disk changes (`git pull` mid-session) go through the same
  [block-level merge](/sync#the-conflict-model) into the Y.Doc. Same-block
  conflict: in-editor version wins, disk is rewritten. No conflict chip
  (shared live doc).
- Last client leave: flush immediately, evict after `evictAfterMs`
  (default 60 s).

Parse and serialize run on the server with your syntax. The first client to
open a document sends the data half of its component specs. Renderers stay
in the browser.

## What changes vs single-user

|                   | FS mirror                         | Collab                                     |
| ----------------- | --------------------------------- | ------------------------------------------ |
| Document lives in | your editor                       | the server's Y.Doc                         |
| Writes to disk    | each client (compare-and-swap)    | the server only                            |
| External edits    | merged client-side, conflict chip | merged server-side, editor wins            |
| Undo              | full local history                | your own edits only                        |
| Raw MDX tab       | available                         | disabled (no merge with a live shared doc) |
| `sync` prop shows | session status                    | connectivity only                          |

Presence carets show each peer's name. A server [auth scope](/auth) `user`
overrides whatever name a client claims. Mirror tabs and collab tabs can
edit the same file: mirror writes enter the authority like any disk change.

## Restarts and the epoch model

No Yjs persistence. **The file is the record.** Each document gets an epoch
when first opened. Server restart (or eviction + reopen) re-seeds from the
file under a fresh epoch. A client with old-epoch history discards its
session and rebuilds from the server. Re-syncing old state would duplicate
the document.

Two loss windows:

- a hard kill can lose edits still inside the save debounce (under a
  second)
- edits typed **while the server was down** are discarded by the epoch
  reset. Edits made while disconnected (server up, network down) buffer
  and converge on reconnect.
