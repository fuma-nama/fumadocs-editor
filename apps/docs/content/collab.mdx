Set `collab` on the `sync` prop:

<include meta='title="collab-editor.tsx"'>../examples/collab.tsx</include>

`user` is the presence identity shown at your caret on other screens.
`collab: true` joins as a guest. Yjs is loaded lazily, so editors that
never enable collab never download it.

## How it works

With collab on, the server holds the document:

- Each open file has one Y.Doc on the server, and the server is the only
  writer to disk. Client edits converge in the Y.Doc; the server serializes
  them to the file, debounced and byte-preserving for untouched blocks.
- Changes on disk (a `git pull` mid-session) go through the same
  [block-level merge](/sync#merging-disk-changes) into the Y.Doc. When the
  same block changed on both sides, the in-editor version wins and the disk
  is rewritten. There is no conflict chip: the live document is shared, so
  there is no local side to keep.
- When the last client leaves, the server flushes immediately and evicts the
  document after `evictAfterMs` (60 s by default).

Parsing and serializing run on the server with your syntax. The first
client to open a document sends the data half of its component specs;
renderers stay in the browser.

## What changes

|                   | Sync                              | Collab                                     |
| ----------------- | --------------------------------- | ------------------------------------------ |
| Document lives in | your editor                       | the server's Y.Doc                         |
| Writes to disk    | each client (compare-and-swap)    | the server only                            |
| External edits    | merged client-side, conflict chip | merged server-side, editor wins            |
| Undo              | full local history                | your own edits only                        |
| Raw MDX tab       | available                         | disabled (no merge with a live shared doc) |
| Status dot        | session status                    | connectivity only                          |

Presence carets show each peer's name. A server [auth scope](/auth) with a
`user` overrides whatever name a client claims. Plain sync tabs and collab
tabs can edit the same file: a sync write reaches the server's document like
any other disk change.

## Restarts

There is no Yjs persistence. The file is the record.

- Each document gets an epoch when it is first opened. A server restart, or
  eviction followed by a reopen, re-seeds the document from the file under
  a fresh epoch.
- A client holding history from an old epoch discards its session and
  rebuilds from the server. Replaying old state would duplicate the
  document.

Two windows where edits can be lost:

- A hard kill can lose edits still inside the save debounce (under a
  second). An orderly shutdown flushes.
- Edits typed **while the server was down** are discarded by the epoch
  reset. Edits made while merely disconnected (server up, network down) are
  buffered and converge on reconnect.
