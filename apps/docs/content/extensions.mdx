[Components](/components) add content: a block with its own markup in the
MDX. Extensions add behaviour on top of the content the document already
has: decorations over text, keyboard shortcuts, plugin state, commands.
They are plain [TipTap extensions](https://tiptap.dev/docs/editor/extensions/custom-extensions),
passed to `extensions`:

```tsx
<MdxEditor extensions={[todoHighlight, askAiShortcut(ask)]} />
```

The MDX does not change: an extension only changes how the visual editor
shows the document and reacts to input. Buttons, counters and panels stay
in your own UI, for example in `header`, or go in the format bubble with
[`bubbleItems`](#buttons-in-the-format-bubble).

Switch **Extensions** off to compare with the default editor. The demo's
model is made up in the page; nothing is sent.

## Buttons in the format bubble

`bubbleItems` adds buttons after the built-in ones (bold, italic, link…)
while text is selected. They use the bubble's look and keep the editor's
focus and selection, on touch screens too.

<include meta='title="ask-ai-item.tsx"'>../examples/extensions.tsx#bubble</include>

| Field       | Does                                                  |
| ----------- | ----------------------------------------------------- |
| `label`     | the button's accessible name and tooltip              |
| `icon`      | what the button shows                                 |
| `shortcut`  | shown in the tooltip; bind it in an extension         |
| `isActive`  | drawn pressed, like Bold over bold text               |
| `isEnabled` | `false` disables the button for the current selection |
| `run`       | called with the live editor                           |

Like `extensions`, the list is fixed for the life of the root. Items only
show in an editable editor, for a text selection.

## Extension Behavior

### Lifecycle

Extensions are applied each time the root builds a live editor: on the
first interaction with the document, and on every return from the MDX
tab. Read-only editors receive them as well. They do not run on the static
first paint or on the MDX tab, so decorations appear once the live editor
has mounted.

The `extensions` array is read once, when the root mounts, as with
`components`. Define it at module level or with `useState`. Arrays or
callbacks passed on later renders are ignored.

### Precedence

Host extensions run alongside the [built-in extensions](#built-in-extensions),
including TipTap's core keymap (Enter, Backspace, paste). When a host
extension and a built-in handle the same key or event at the same
`priority` (default `100`), the built-in runs first. To take precedence,
set a `priority` higher than that of the extension it competes with.

### Restrictions

An extension is left out, with a console error that gives the reason,
when it:

- adds a node or a mark. Nodes and marks are content, which the MDX
  serializer cannot write; use a [component](/components) instead.
- uses a name that another extension has already registered.
- adds a command that already exists.

Give each ProseMirror plugin a unique `PluginKey`.

### Collaboration

Under [collab](/collab), `appendTransaction` also receives the
transactions that apply remote edits. Ignore transactions that carry the
`y-sync$` meta; otherwise every collaborator applies the change again.

## Built-in extensions

Your extensions run next to the ones the editor is built from. Their
source is the place to check which names, commands and keys are taken:

- TipTap's [core extensions](https://github.com/ueberdosis/tiptap/tree/main/packages/core/src/extensions):
  Enter, Backspace, paste, drop
- StarterKit, lists, tables, images and the MDX nodes, from
  [`editorExtensions`](https://github.com/fuma-nama/fumadocs-editor/blob/dev/packages/core/src/extensions/kit.ts)
- one node per [component spec](/components)
- the editor's own, from the list
  [`LiveEditor`](https://github.com/fuma-nama/fumadocs-editor/blob/dev/packages/ui/src/live-editor.tsx)
  builds, with their keys in
  [`keymap.ts`](https://github.com/fuma-nama/fumadocs-editor/blob/dev/packages/ui/src/components/keymap.ts)

In a running editor, `editor.extensionManager.extensions` lists them all.
