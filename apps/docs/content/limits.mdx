## General

- **React 19 only.** The editor is a client component; SSR apps mount it
  inside `'use client'`. For a server-rendered first paint, pass your
  site's rendered MDX as `staticFallback`. The editor swaps in on hydration
  without a parse on the critical path.
- **Word pastes** are coerced through the schema, so marks, tables and
  lists survive. One upstream exception: Word numbered lists arrive as
  literal `1. Item` paragraphs. That is ProseMirror's clipboard parser.
- **Not yet editable:** `<CodeBlockTabs>`, plain `<Tabs>` and footnotes are
  verbatim-only for now ([details](/syntax#not-yet-editable)).

## Engine differences

Exercised on Chromium, WebKit and Firefox, desktop and touch. Behaviour is
aligned, except:

- **WebKit** takes one extra arrow-key stop when leaving inline math. A
  ProseMirror boundary quirk, cosmetic.
- Clicks on dead chrome (tab-strip padding, the gap in a code-block header)
  are no-ops. Clicks on real component chrome place the caret in the
  nearest region.

## Touch

Verified against real WebKit and Chromium with touch events (Playwright
device emulation), not yet on physical hardware:

- On coarse pointers a toolbar sits above the on-screen keyboard while the
  editor is focused: the element type menu, insert, marks, the active
  component's panel, undo and redo. No CSS knows the keyboard's height, so
  its offset is written from the visual viewport's own events, straight to
  the element; the visual viewport already excludes iOS Safari's keyboard
  accessory bar.
- Drag and drop is the browser's own. A touch on a component's chrome (not
  its text) makes it draggable for that touch, the way ProseMirror does on
  mousedown, so an iOS long-press drags it from empty space or its ⋯
  handle. Android has no native touch drag and drop; its panel offers move
  up and down.
- The editor's own chrome (node views rendered by React) is never read
  back as a virtual-keyboard edit. TipTap's mobile heuristic would treat
  each mount as one and synthesize Enter from it.
- Autocorrect, autocapitalize and spellcheck are suppressed on the editing
  surface; autocorrect and dictation (`insertReplacementText`, not key
  events) are still unverified.

## Collaboration

- A hard kill of the sync server can lose edits still inside its save
  debounce (under a second). An orderly shutdown flushes.
- Edits typed **while the server was down** are discarded when it comes
  back ([epoch reset](/collab#restarts)). Edits made while merely
  disconnected converge on reconnect.
- The raw MDX tab is disabled during collab.
