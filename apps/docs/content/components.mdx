## The model

The editor does not render your real components. Real components own state
and interactivity (tabs switch, accordions collapse, links navigate), which
fights an always-editable surface. Each component gets a **spec**: how
attributes and children map to editable regions, plus a lightweight
**renderer** that mirrors the look around those regions.

The spec is data, so the editor can keep structure (see
[the guard](#what-the-guard-guarantees)) no matter what the renderer does.
Components without a spec still round-trip byte-for-byte. They render as a
neutral card and are edited as source.

## The regions model

`children` in the render props is **all regions in document order**: here
the `title` inline region, then the `body` block region. You place them
once; there is not one slot per region.

To style a region, target `data-region="<name>"` from the wrapper (the
example bolds the title with `[&_[data-region=title]]:font-medium`).

Everything else the renderer draws is chrome. Mark it
`contentEditable={false}` (the example's "Soon" badge) so the caret cannot
enter it. Chrome clicks put the caret in the nearest region.

## Props vs literals

JSX attributes reach the renderer in two forms:

| Render prop | Holds                                  | Example                                  |
| ----------- | -------------------------------------- | ---------------------------------------- |
| `props`     | plain-string attributes                | `type="info"` → `props.type === "info"`  |
| `literals`  | static values of expression attributes | `soon={true}` → `literals.soon === true` |

`setProp(name, value)` writes a string attribute. `setLiteral(name, value)`
rewrites an expression from a literal (source text is derived). Use them
for controls the renderer owns (Callout type picker is `setProp`). An
expression that is not a static literal (variable, call) stays out of
`literals` and is edited as source in the attributes panel.

## Spec reference

Structural fields (`ComponentSpec`, from `@fumadocs-editor/core`):

| Field              | Purpose                                                                                       |
| ------------------ | --------------------------------------------------------------------------------------------- |
| `name`             | JSX tag name                                                                                  |
| `label`            | display name in menus; defaults to `name`                                                     |
| `attributeRegions` | string attributes edited as inline regions                                                    |
| `contentRegion`    | element _text content_ as an inline region (`<include>./path.mdx</include>`)                  |
| `childrenRegion`   | children as one block region; `fromAttribute` folds an attribute (Card `description`) into it |
| `childComponent`   | children are nested component instances (Cards → Card); array for several tags                |
| `listLike`         | Enter/Backspace grow and shrink the child list (file trees)                                   |
| `itemsAttribute`   | parent array attribute edited as a label region in each child (Tabs `items`)                  |
| `props`            | panel-edited attributes: `string`, `number`, `boolean`, `enum`, `expression`                  |
| `insert`           | slash-menu fragment; omit for child-only specs                                                |

UI fields (`UiComponentSpec` adds):

| Field            | Purpose                                                             |
| ---------------- | ------------------------------------------------------------------- |
| `render`         | mirror renderer                                                     |
| `icon`           | glyph in menus                                                      |
| `filePathRegion` | file-path region; autocompletes via the [file provider](/providers) |

`contentRegion`, `childrenRegion`, and `childComponent` are mutually
exclusive. A spec with none of them is a leaf (props only, like
`GithubInfo`). For containers, the built-in specs are the reference:
`cardsSpec`/`cardSpec`, `filesSpec` (`listLike`), `tabsSpec`
(`itemsAttribute`).

## What the guard guarantees

A structure guard runs on every transaction and heals anything that would
break a component's declared shape:

- a component always has exactly its declared regions; a paste that brings
  extra blocks is folded into the right region
- selections spanning region boundaries cannot tear a component into
  valid-but-wrong pieces (typing, paste, delete)
- structural moves only place components into parents whose
  `childComponent` accepts them; invalid MDX is unproducible
- a renderer throw degrades that one component to a fallback card with
  regions still editable; the document stays lossless, siblings untouched.
  Fixing the attribute heals it in place.
