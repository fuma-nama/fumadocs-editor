## The model

The editor never renders your real components. A real component owns state
and interactivity — tabs switch, accordions collapse, links navigate — and
all of that fights an always-editable surface. Instead, each component gets a
**spec**: a structural description of how its attributes and children map to
editable regions, plus a lightweight **renderer** that mirrors its look
around those regions.

That split is also what keeps documents safe: the spec is data, so the editor
can guarantee structure (see [the guard](#what-the-guard-guarantees)) no
matter what the renderer does. Components without a spec still round-trip
byte-for-byte — they render as a neutral card and are edited as source.

## The regions model

`children` in the render props is **all regions in document order** — here
the `title` inline region followed by the `body` block region. You place
them once; you don't get one slot per region.

To style regions individually, target them from your wrapper: each region
renders with `data-region="<name>"` (the example bolds the title with a
Tailwind arbitrary variant, `[&_[data-region=title]]:font-medium`).

Everything else the renderer draws is chrome. Mark it
`contentEditable={false}` — like the example's "Soon" badge — so the caret
and selection can never wander into it. The editor's click policy treats
chrome clicks as "put the caret in the nearest region".

## Props vs literals

JSX attributes reach the renderer in two forms:

| Render prop | Holds                                  | Example                                  |
| ----------- | -------------------------------------- | ---------------------------------------- |
| `props`     | plain-string attributes                | `type="info"` → `props.type === "info"`  |
| `literals`  | static values of expression attributes | `soon={true}` → `literals.soon === true` |

`setProp(name, value)` writes a string attribute; `setLiteral(name, value)`
rewrites an expression attribute from a literal (the source text is derived).
Use them for controls the renderer owns — the Callout's type picker is
`setProp` in action. An expression that isn't a static literal (a variable, a
function call) doesn't appear in `literals`; it stays editable as source in
the attributes panel, and everything still round-trips.

## Spec reference

Structural fields (`ComponentSpec`, from `@fumadocs-editor/core`):

| Field              | Purpose                                                                                              |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| `name`             | JSX tag name — the component's identity                                                              |
| `label`            | display name in menus; defaults to `name`                                                            |
| `attributeRegions` | string attributes edited as inline regions                                                           |
| `contentRegion`    | the element's _text content_ as an inline region (`<include>./path.mdx</include>`)                   |
| `childrenRegion`   | children as one block region; `fromAttribute` folds an attribute (like Card's `description`) into it |
| `childComponent`   | children are nested component instances (Cards → Card); array for several tags                       |
| `listLike`         | Enter/Backspace grow and shrink the child list (file trees)                                          |
| `itemsAttribute`   | a parent array attribute edited as a label region in each child (Tabs' `items`)                      |
| `props`            | panel-edited attributes: `string`, `number`, `boolean`, `enum`, `expression`                         |
| `insert`           | fragment inserted by the slash menu; omit for child-only specs                                       |

UI fields (`UiComponentSpec` adds):

| Field            | Purpose                                                                        |
| ---------------- | ------------------------------------------------------------------------------ |
| `render`         | the mirror renderer                                                            |
| `icon`           | glyph shown in menus                                                           |
| `filePathRegion` | region holding a file path — autocompletes via the [file provider](/providers) |

`contentRegion`, `childrenRegion` and `childComponent` are mutually
exclusive; a spec with none of them is a leaf (props only, like
`GithubInfo`). For container patterns, the built-in specs are the best
reference: `cardsSpec`/`cardSpec` (plain container), `filesSpec` (`listLike`
tree), `tabsSpec` (`itemsAttribute`).

## What the guard guarantees

A structure guard runs over every transaction and heals anything that would
break a component's declared shape:

- a component always has exactly its declared regions — a paste that smuggles
  extra blocks in is folded into the right region,
- selections spanning region boundaries can't tear a component into
  valid-but-wrong pieces (typing, paste, and delete are all checked),
- structural moves only place components into parents whose `childComponent`
  accepts them — invalid MDX is unproducible by construction,
- a renderer that throws degrades that one component to a fallback card with
  its regions still editable; the document stays lossless and siblings are
  untouched. Fixing the attribute heals it in place.
