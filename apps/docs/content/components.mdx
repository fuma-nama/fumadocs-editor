Without a spec, a component's children stay editable and its tags are
edited as text. A spec makes it a real block, with editable regions, a
slash-menu entry and an attributes panel.

The editor never renders your real components. Each one gets:

- a **spec** describing which attributes and children are editable
- a **renderer**, a lightweight look-alike drawn around them

## Regions

`children` contains every region in document order: here `title`, then
`body`.

- Style a region with `regions`, or with `[data-region="<name>"]`.
- Mark decorations `contentEditable={false}` so the caret cannot enter them.
- Leave some chrome around the regions (an icon, a border, padding):
  double-clicking it selects the component.

<Callout title="Nested components">
  A component that sits inside another one needs a spot for the touch drag handle: an empty element
  with `data-fde-controls` in its chrome.
</Callout>

## Props and literals

Attributes reach the renderer in two forms:

| Render prop | Holds                    | Example                                  |
| ----------- | ------------------------ | ---------------------------------------- |
| `props`     | string attributes        | `type="info"` → `props.type === "info"`  |
| `literals`  | static expression values | `soon={true}` → `literals.soon === true` |

Change them from the renderer with `setProp(name, value)` and
`setLiteral(name, value)`. Expressions that are not literals, like a
variable, are edited as source in the attributes panel.
