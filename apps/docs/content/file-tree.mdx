`FileTree` shows the mirrored directory the way Fumadocs' sidebar does and
edits it in place: new pages and folders, deletion, drag and drop order,
separators. Every change lands on disk as a file or a `meta.json` entry, so
the site's navigation follows.

<include meta='title="workspace.tsx"'>../examples/file-tree.tsx</include>

`useWorkspace` subscribes to the tree over the same websocket the editor
uses and hands back `run` for changes. Both come from the
[sync server](/sync); with no `transport` they share the page's default one.

## What it edits

| Action                    | On disk                                                      |
| ------------------------- | ------------------------------------------------------------ |
| New page                  | `<slug>.mdx` with a frontmatter `title`                      |
| New folder                | `<slug>/meta.json` with the title and `<slug>/index.mdx`     |
| Move a row, new separator | the folder's `pages` in `meta.json`, rewritten minimally     |
| Delete a page             | the file, and its `pages` entry when nothing else answers it |

A page or folder typed as `Guides/Getting started` nests: the path is the
slug of every segment, the title is the last one.

<Callout>
  A folder without a `meta.json`, or one whose `pages` ends in `...`, keeps listing new pages
  automatically. Only explicit lists get the new key appended.
</Callout>

## Keyboard

| Keys                 | Does                           |
| -------------------- | ------------------------------ |
| `↑` `↓` `Home` `End` | Move between rows              |
| `←` `→`              | Close or open a folder         |
| `Alt+↑` `Alt+↓`      | Move the row within its folder |
| `Enter` in a draft   | Create; `Escape` cancels       |

On touch screens rows drag from the grip; with a mouse any row drags.

## Permissions

Commands run under the connection's [scope](/auth): creating or deleting a
page needs `write` on its path, reordering needs `write` on the folder's
`meta.json`. The tree only lists what `read` allows. A refusal shows at the
bottom of the tree.

## Custom backends

The tree rides two optional calls on `SyncTransport`. A backend that has
folders and an order can implement them; one that does not simply omits
them and `useWorkspace` throws.
