Sync connects the editor to a folder of `.md` and `.mdx` files:

- edits autosave to disk
- changes on disk (a `git pull`, a save from your IDE) merge into the open
  document without moving your caret
- a block changed on both sides becomes a conflict you resolve in one click

## Saving

- Autosave runs 800 ms after you stop typing, and at most 5 s after the
  first unsaved change.
- `⌘S`, leaving the window and closing the page save immediately.
- A save never overwrites a file it has not seen. If the file changed on
  disk meanwhile, that change is merged in first.
- When the same block changed on both sides, your version is kept. Saving
  pauses until you pick **keep mine** or **take disk**.
- Without [write access](/read-only), edits stay in the editor. They are
  saved once access comes back.

## Status

The status dot shows where the document stands:

| Status     | Meaning                                       |
| ---------- | --------------------------------------------- |
| `synced`   | disk matches what you see                     |
| `dirty`    | edits waiting for autosave                    |
| `saving`   | a save is in flight                           |
| `conflict` | the same block changed locally and on disk    |
| `offline`  | disconnected; edits are kept and saved later  |
| `denied`   | the server rejected your [credentials](/auth) |

To show it elsewhere:

- `sync.onStatus` is called with the current status once the document is
  open (again when `path` changes), then on every change.
- `useSyncStatus()` returns the same status inside `MdxEditor.Root`.

`sync.onWritable` works the same way for write access. See
[Read-only](/read-only#with-auth).

## Without `MdxEditor`

The `sync` prop is built on `client.open`. Use it directly for a custom
status UI or a non-React shell:

<include meta='title="custom-document.tsx"'>../examples/sync-document.tsx</include>

- `editor` is anything with `getMarkdown`, `applyExternalMarkdown`,
  `setMarkdown` and `markSaved`. The editor ref qualifies.
- Load `opened`'s `text` into the editor, and call `changed()` on every
  edit.
- Read write access from `writable()`, not from `opened`: the server
  answers again after every reconnect. `subscribe` fires when it changes.
- A client holds one document per path.
