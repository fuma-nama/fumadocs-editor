## Overview

`@fumadocs-editor/sync` keeps the editor and a directory of `.md`/`.mdx`
files in sync both ways:

- the editor autosaves with compare-and-swap writes
- disk changes (`git pull`, IDE save) merge into the live document without
  moving the caret

The files are the source of truth. The editor is another writer.

```bash
npm install @fumadocs-editor/sync
```

## The dev server

Mount the sync server on Vite:

<include meta='title="vite.config.ts"'>../examples/sync-vite.ts</include>

`root` is the mirrored directory, resolved against the Vite project root.
Three endpoints (constants from `@fumadocs-editor/sync`):

| Endpoint         | Constant          | Purpose                                              |
| ---------------- | ----------------- | ---------------------------------------------------- |
| `/__fde_sync`    | `SYNC_ENDPOINT`   | sync websocket                                       |
| `/__fde_upload`  | `UPLOAD_ENDPOINT` | media uploads (`POST`, stored under `<root>/assets`) |
| `/__fde_asset/*` | `ASSET_ENDPOINT`  | stored assets                                        |

Also accepts every [`createSyncServer` option](#standalone-server), including
[`authenticate`](/auth).

<Callout type="warn" title="Keep Vite away from the mirrored files">
If the mirrored directory sits inside your Vite root, exclude it from the
watcher. Tailwind's source scan will otherwise invalidate CSS and reload the
page on every save:

```ts title="vite.config.ts"
export default defineConfig({
  server: { watch: { ignored: ["**/content/docs/**"] } },
});
```

Do not import mirrored files as modules (`?raw` included).

</Callout>

### Standalone server

`createSyncServer` is the same server as plain handlers on any Node HTTP
server:

<include meta='title="server.ts"'>../examples/sync-server.ts</include>

Options: `authenticate` ([auth](/auth)), `evictAfterMs` (how long an open
collab doc outlives its last client, default 60 s), `upload` limits
(default 10 MiB, `image/*`; oversized or wrong-type bodies are refused
before store).

## The editor side

Pass a path. The editor does the rest: initial read, autosave (800 ms after
the last change, 5 s max), live merge, conflicts, flush on Cmd-S and page
leave.

<include meta='title="editor.tsx"'>../examples/sync-editor.tsx</include>

With no `transport`, editors share one websocket to the current host's
dev server. Pass your own for [auth](/auth) or a custom backend, and
`onOpen` for the file's [scope data](/auth#exposed-data) after read.

### Status

The dot beside the mode tabs is the session status. `onStatus` mirrors it.

| Status     | Meaning                                                |
| ---------- | ------------------------------------------------------ |
| `synced`   | disk matches what you see                              |
| `dirty`    | local edits waiting for autosave                       |
| `saving`   | write in flight                                        |
| `conflict` | same block changed locally and on disk                 |
| `offline`  | connection lost; edits keep, saves resume on reconnect |
| `denied`   | server rejected credentials ([auth](/auth))            |

### The conflict model

Block-level three-way merge. Base is the last-synced document. A block is
"the same" when the serializer would emit it byte-identically. Disk-only
changes apply as one non-undoable transaction; the caret stays put. A block
edited on **both** sides is a conflict: local version kept, writes paused,
chip with keep mine (overwrite disk) or take disk (drop local).

## Custom backends

The dev server implements `SyncTransport`. A database, CMS, or browser
file-system handle needs four calls:

```ts
interface SyncTransport {
  list(): Promise<string[]>;
  read(path: string): Promise<ReadResult>;
  write(path: string, text: string, baseVersion: string): Promise<WriteResult>;
  watch(path: string, onChange: (state: FileState) => void): () => void;
  onStatus?(listener: (status: ConnectionStatus) => void): () => void;
}
```

Documents are root-relative posix paths. `version` is an opaque CAS token:
`write` must fail with the current state when `baseVersion` no longer
matches. That is all the session needs to merge and retry. `onStatus` is
optional (omit if the backend cannot go offline). Pass the transport to
`sync` and the rest applies unchanged.

### Your own session

`sync` is built on public `createFileSession`. Use it for a custom status
UI, a non-React shell, or a session shared by several views:

<include meta='title="custom-session.tsx"'>../examples/sync-session.tsx</include>

`document` is anything with `getMarkdown`, `applyExternalMarkdown`,
`setMarkdown`, `markSaved`. The session does not depend on React. Call
`changed()` from `onChange` and `flush()` when a save should happen now.
