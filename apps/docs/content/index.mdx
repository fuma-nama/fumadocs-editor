## Introduction

Fumadocs Editor is a visual editor for MDX. It renders prose, code, tables,
and MDX components as an editable page. The file stays the source of truth.

- **Lossless round-trip**: untouched blocks emit byte-for-byte, so a one-line
  edit is a one-line diff. Unknown constructs are preserved, not reformatted.
- **Spec-driven components**: fumadocs-ui (Callout, Cards, Tabs, Files, …)
  is editable in place. [Your own components](/components) take a small spec.
- **Instant open**: static first paint, then the editing runtime hydrates.
  Keystrokes typed during load are not dropped.

## Installation

```bash
npm install @fumadocs-editor/ui
```

React 19. Client component: in SSR apps, mount it inside `'use client'`.

## Styles

Tailwind CSS v4 and fumadocs `fd-*` tokens. Import the preset after Tailwind:

```css title="app.css"
@import "tailwindcss";
@import "@fumadocs-editor/ui/css/preset.css";
```

The preset registers `--color-fd-*` (fumadocs `neutral` defaults) and tells
Tailwind to scan the package. On a Fumadocs site, the site theme already
defines those tokens and wins.

- `defaultValue` is the initial MDX. Uncontrolled after that, like
  `<textarea defaultValue>`.
- `onChange` fires with serialized MDX, debounced. `ref.getMarkdown()` if
  you'd rather pull.
- fumadocs-ui components work out of the box. Add [your own](/components)
  with `components={[...fumadocsUiComponents, mine]}`. Unlisted components
  still round-trip; they just aren't editable in place.

## Theming

`fd-*` tokens follow a `.dark` class, so a Fumadocs / `next-themes` site
themes the editor with no extra setup. Standalone, wrap it:

<include meta='title="standalone.tsx"'>../examples/theming.tsx</include>

`EditorThemeProvider` tracks `light | dark | system`, persists to
`localStorage`, and sets the class on a wrapper. Pin one editor with
`theme="light"` or `theme="dark"`.
